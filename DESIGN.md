# Как устроено приложение Country Search

## 1. Структура проекта и разделение логики

Чтобы логику поиска можно было легко проверять автотестами без запуска браузера, я разделил проект на независимые слои:

* **`src/utils/` (инструменты и типы):**
  * `types.ts` — описание того, какие данные приходят от сервера (`RawCountry`) и в каком виде они нужны нашим карточкам (`Country`).
  * `debounce.ts` — функция задержки ввода, которая ждёт паузу в печати перед отправкой запроса.
* **`src/api/` (работа с сетью и данными):**
  * `errors.ts` — свой класс ошибки `HttpError` (хранит код ответа сервера, например `500`) и функция `classifyError`, которая помогает понять причину сбоя: отменили ли запрос мы сами, вышел ли таймаут, упал ли сервер или пропал интернет.
  * `searchCountries.ts` — функция запроса к API `countries.dev/name/{query}`. Она кодирует текст запроса, превращает ответ `404` в пустой массив `[]` (ведь «страна не найдена» — это не поломка), ограничивает время ожидания через `AbortSignal.timeout` и выбрасывает `HttpError` при других плохих статусах.
  * `mapCountryResponse.ts` — чистая функция-переводчик: берёт громоздкий объект от API и достаёт только нужные нам поля (название, флаг, столицу, регион, население, языки, валюту, площадь и границы), подставляя «Нет данных», если чего-то не хватает.
* **`src/store/` (управление состоянием):**
  * `searchController.ts` — главный координатор (`CountrySearchController`). Он хранит текущее состояние экрана (`idle`, `loading`, `success`, `empty`, `error`), управляет отменой старых запросов и умеет повторять последний запрос при нажатии кнопки «Повторить».
* **`src/ui/` и корень проекта (интерфейс):**
  * `index.html`, `styles.css`, `createElement.ts` и файл отрисовки интерфейса. Весь HTML создаётся безопасно через `document.createElement` и `textContent` (без `innerHTML`), а подробная карточка страны открывается в нативном окне `<dialog>`.

## 2. Как проходит поисковый запрос и как решаются гонки (Race Condition)

Главная проблема живого поиска: если быстро набрать `sp`, а потом дописать `ain` (`spain`), старый запрос может вернуться позже нового и перезаписать свежие результаты устаревшими.

В проекте это решается так:

1. **Мгновенная отмена при новом нажатии:** как только пользователь меняет текст в поле ввода, вызывается `handleInput()`. Первым делом он запускает `abortController.abort()`. Если предыдущий сетевой запрос ещё выполнялся, браузер сразу обрывает его соединение.
2. **Пустое поле:** если после удаления пробелов по краям строка пустая, запрос в сеть не уходит, а экран сразу очищается (статус `idle`).
3. **Пауза перед отправкой (`debounce`):** если текст есть, запускается таймер на 300 мс. Пока пользователь продолжает печатать, таймер каждый раз перезапускается, чтобы не отправлять лишние запросы на каждую букву.
4. **Двойной контроль отмены (`AbortSignal.any`):** когда 300 мс прошли, создаётся новый `AbortController`. Его сигнал объединяется с сигналом таймаута (`AbortSignal.timeout(5000)`). Запрос прервётся, либо если пользователь начнёт печатать снова, либо если сервер не ответит за 5 секунд.
5. **Разбор ответа и ошибок:**
   * Если пришёл список стран — показываем карточки (`success`).
   * Если сервер вернул `404` — показываем спокойное сообщение «Ничего не найдено» (`empty`).
   * Если запрос упал в `catch`, проверяем причину через `classifyError`: если это `AbortError` (наша собственная отмена при новом вводе), мы просто игнорируем её и не пугаем пользователя ошибкой. Если же пропал интернет, вышел таймаут или ответил `500` — показываем блок ошибки с кнопкой «Повторить».

## 3. Оценка скорости работы и памяти

* **Функция `debounce`:** работает за **O(1)** по времени и памяти — она просто хранит один идентификатор таймера и перезаписывает его при каждом вызове.
* **Преобразование одной страны (`mapCountryResponse`):** проходит по спискам языков, валют и границ страны, поэтому сложность равна **O(L + C + B)** (где L, C и B — количество этих элементов). На практике у любой страны их совсем немного, поэтому функция работает почти мгновенно — за **O(1)**.
* **Отрисовка списка результатов:** если API вернул *N* стран, мы проходим по массиву один раз для преобразования данных и один раз для создания карточек в DOM. Итоговая сложность по времени и памяти — **O(N)** (в мире около 250 стран, поэтому *N* всегда небольшое).

## 4. Компромиссы, ограничения и что можно улучшить

* **Сборка через TypeScript без бандлера:** мы компилируем `.ts` файлы напрямую в ES-модули через `tsc`. Плюс такого подхода — простая настройка без Webpack или Vite. Минус — браузер загружает несколько отдельных JS-файлов вместо одного сжатого бандла.
* **Нет кэширования запросов:** если пользователь ввёл `Spain`, стёр и снова ввёл `Spain`, приложение сделает повторный запрос на сервер. В будущем можно добавить простой кэш в памяти (`Map`), чтобы мгновенно отдавать уже загруженные результаты.
* **Зависимость от внешнего API:** приложение работает напрямую с публичным сервером `countries.dev` и картинками флагов `flagcdn.com`, поэтому при недоступности этих сервисов поиск работать не будет.
